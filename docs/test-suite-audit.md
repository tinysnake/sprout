# Test-suite unique-protection audit (#133)

Scope: the final 1,372-test inventory after the split, including the Web DOM suite. This is a **review recommendation only**: no test is changed or removed here. A test title alone is not proof of redundancy; the candidates below were inspected against their assertions and neighbouring tests. Tests not listed here retain a plausible separate boundary, failure mode, backend, or observable contract; that is not a guarantee that every assertion is effective. In particular, repeated names generated by memory/SQLite loops represent different integration boundaries, not necessarily duplicate coverage.

| Flagged test | Risk → test (realistic defect and overlapping protection) | Recommendation |
| --- | --- | --- |
| `src/store/schema.test.ts` — “schema constants declare supported version range” | A version constant drifts → direct literal comparisons fail; migration/open tests in the same file already fail if the declared range is incompatible with actual schema creation and migration. Literal version assertions also require maintenance on every intentional version change. | **Merge** the supported-range invariant into the schema opening/migration tests; delete the hard-coded constant-only case in a separately approved change. |
| `web/src/modules/agents/agents.service.test.ts` — “the fixture covers ready, attention, unavailable, archived, and not-observed rows distinctly” | Fixture data loses a state → fixture-only check fails; “every fixture row renders its stable identity and no host facts” and the status-evaluation test use the fixture to check observable behaviour. | **Merge** fixture-state preconditions into the observable rendering/status case, then remove the fixture-shape-only test after verifying the rendering test actually checks each state. |
| `web/src/modules/agents/agents.service.test.ts` — “attribution fixtures carry no transport addresses or paths” | A fixture accidentally contains a host path → this checks test data rather than the production privacy boundary; “every fixture row renders its stable identity and no host facts” checks the rendered outcome. | **Merge** the host-fact assertion into the rendering test; retain the fixture check only if it is deliberately a reusable privacy contract for other suites. |
| `src/host-config.test.ts` — “the host proxy is empty when the host declares none” | A missing host variable unexpectedly creates a proxy → the empty-host defaults test already exercises the same input and output surface. | **Merge** the proxy absence assertion into “an empty host environment takes exactly the documented defaults”; verify that the latter tests the same proxy field before deletion. |
| `src/host-config.test.ts` — “an empty numeric host setting keeps the runtime conversion it had before” | Empty text stops coercing to zero → this guards a JavaScript coercion accident rather than a deliberate configuration policy. The defaults test covers missing values, but not explicit empty strings. | **Keep pending policy decision**: if compatibility with explicit empty values is required, keep; otherwise remove the test and specify parsing behaviour rather than pinning language coercion. |

Not flagged despite similar-looking titles: schema safety-copy and migration cases cover distinct persisted data/reopen failures; privacy tests distinguish concrete sensitive-input formats and non-sensitive false positives; Agent creation and reconfiguration cases protect different lifecycle transitions. Backend loops exercise real SQLite separately from in-memory storage. Constructor/getter/setter-shaped assertions embedded in behavioural tests are not grounds to remove the whole test while its lifecycle or privacy oracle remains unique.

Review method: compare test titles and assertion surfaces across the complete post-split inventory, grouping by contract, boundary, and failure mode; nominate only cases where another named test plausibly subsumes the same regression. Follow-up review should validate each proposed merge by temporarily deleting the candidate on a separate branch and checking that the remaining test fails under the same targeted mutation. No deletion is authorized by this document.
