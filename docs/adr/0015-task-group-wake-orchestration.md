# Task groups use bounded hybrid wake orchestration

Every explicitly submitted Task-group Message enters a hybrid wake decision, independent of the Project wake policy: mentions and broadcasts resolve deterministically; otherwise `question` and `escalation` address the Task lead; otherwise current Task assignments and exact declared responsibility labels resolve first; only remaining ambiguity may invoke a wake model; an empty, invalid, unavailable, failed, or timed-out result falls back to the Agent lead. Omitted Message `kind` means `status`. This extends ADR-0014's temporary per-Task scope and ADR-0007's persistence-before-wake and sender-exclusion rules. A Human lead receives no inferred Agent delegation, including assignment-based delegation, while explicit mentions still address Agents normally. Invalid mentions retain their per-target failures; an Agent lead is the last-resort recipient when no valid mentioned Agent remains.

The wake-time guarantee is at least one eligible Agent wake for an Agent-led group. Sender exclusion, an unavailable lead, missing Task facts, and the chain bound take precedence: when those make a wake impossible, the original Message remains durable and produces Human Attention instead of self-waking, widening membership, or disappearing. An unanswered Message has a fixed five-minute development-stage idle deadline measured from persistence. If no causal Agent run has begun working and no Agent reply answers it, Sprout re-wakes an eligible Agent lead once using a distinct durable wake identity; another five minutes without work or a reply emits one Human Attention signal. A Human-led group, or an ineligible lead, emits the signal at the first deadline without a forced wake. Working and answered Messages settle their idle obligation; terminal groups stop orchestration. These deadlines do not restart failed runs or modify Task authority, leases, or lifecycle.

Deterministic wakes are persisted with the Message inside the existing Task lifecycle serialization turn. Ambiguous routing runs after persistence, outside that turn and outside the posting request. Its injected model port receives only a bounded Message excerpt scanned by `redactSensitiveText` and bounded current Agent candidates. Excerpt redaction has ADR-0007's [limited wake-model privacy guarantee](0007-message-and-wake-routing-semantics.md#wake-model-privacy-guarantee-amended-2026-10-07): recognized patterns are removed, but unlabelled opaque values in free text may reach the model. The port has a thirty-second timeout with cancellation capped by the earliest pending idle deadline, and makes at most one call per Message. A durable claim precedes inference; restart or a competing coordinator encountering the claim uses lead fallback rather than calling again. Membership and writability are rechecked after inference. Durable orchestration stage events and their wake requests use stable delivery keys, so restart reconstructs the same routing, re-wake, and escalation stages. Message intent upgrades through schema v29's safety-copy and transactional migration, preserving legacy Messages as `status`. Timers only request a sweep; durable Message and event timestamps decide whether a deadline elapsed. Sprout adopts Paperclip's durable scheduler-receipt principle as design, without copying code, while retaining its own Task lead and Human authority boundaries.

An Agent-authored causal chain may contain at most two explicitly submitted Messages before escalation: A→B may wake B, B→A may wake A, and a further Agent hop emits Attention instead of continuing the chain. The posting envelope carries `inReplyTo` to identify the chain; each ancestor must belong to the same Task-group scope. Automatically projected replies and orchestration events never become conversational routing inputs. Independent explicit sends remain distinct inputs, not inferred reply chains. The sender is excluded from every deterministic, assignment, model, fallback, and re-wake target. The durable `task-group-unanswered` Project event uses `human-action-required`; its stable event identity and a content-free projection exposing Message, scope, Project, and time form the Feed/Attention port for #213. Human resolution acknowledges that event and never retries Agent work. The #212 posting envelope supplies the optional intent and causal relationship; there is no work-item assignment map yet, so the initial deterministic assignment source is the Task's assigned Agent plus declared responsibility keys.
