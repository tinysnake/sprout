# Codex runs through the app-server JSON-RPC transport

> Current scope: [ADR-0020](0020-defer-privacy-hardening-and-redaction.md) supersedes this decision's privacy-specific guarantees and redaction requirements. Authentication, access permissions, execution controls, and other independent requirements remain effective.

Codex offers two non-interactive surfaces and they are not equivalent. `codex exec --json` is a one-shot process, but it does **not stream**: a whole turn yields exactly four events (`thread.started`, `turn.started`, `item.completed`, `turn.completed`) and the agent message arrives as one complete blob after generation finishes. `codex app-server --listen stdio://` speaks JSON-RPC over stdio and emits `item/started` and `item/completed` per item, including `commandExecution` tool calls as they occur.

We decided to run Codex through **app-server**, because `docs/goal.md` makes "the human can always observe, interrupt, and correct agents" a product principle, and blob delivery defeats that for the engine we expect to use most. The cost is that Sprout must supervise a long-lived child process — start it, health-check it, and restart it — and must tolerate a run dying mid-turn. We accepted that cost, and it is now a requirement on O4's recovery work rather than a surprise.

For development and conformance compositions, the Host Codex profile pins Codex CLI `0.159.3` and uses the app-server's experimental dynamic-tool API to expose only run-scoped remote workspace and approved Project MCP tools. `initialize` opts into `experimentalApi`; `thread/start` receives the typed tool catalog; server `item/tool/call` requests return to the Sprout Engine adapter and dispatch through the shared Environment Operations seam. The Host profile disables native shell and ambient local tools under its host isolation policy. Its sandbox permits reads from the private runner and configured Codex home, while writes stay within those areas and authentication/configuration files remain protected. Its non-inference readiness probe verifies the pinned CLI version, account, exact model, every disabled feature through `experimentalFeature/list`, and acceptance of the Sprout dynamic-tool catalog. The current implementation reports an allowlisted probe step and bounded error category on failure; this is an observation, not a privacy preservation requirement under ADR-0020. The app-server receives a reduced process environment with only its runtime PATH, private HOME/TMPDIR, and explicit CODEX_HOME; host credentials from unrelated environment variables are not inherited. The current implementation redacts Codex output before producing Engine events or turn results and limits durable tool events. ADR-0020 defers privacy hardening and makes this redaction optional for future implementation work; event selection and bounds should serve useful progress and stable product records. Production Runtime composition remains gated while #248's named host-authority-exclusion prerequisite is unresolved; explicit model configuration does not lift that gate, and this route does not claim host-authority exclusion. The experimental protocol is version-pinned and must be re-verified when the Codex CLI changes.

The alternative — ship Pi first and defer Codex — was rejected because O1's claim is that one run interface covers two real engines; proving it against a single engine would defer the hardest part of the design.

**Consequences**: a Codex run is not a single child process. Sprout needs a session-supervision component, and O4's recovery check must cover daemon death, not just an interrupted run. Pi needs no equivalent, so the shared interface must not assume that every engine has a matching lifecycle. Host-run Codex's accepted file-data route does not establish the separate host-authority exclusion prerequisite recorded in #248.

**Note on engine scope**: M1 names Codex and Pi. Ticket #251 adds Claude Code as an adapter through the existing Engine Interface without changing this Codex app-server decision. The Host Claude executor pin is Claude Code CLI `2.1.294` and its stream-JSON/MCP protocol. Its read-only user setting resolves to `group/auto-mimo-v2-6-flash[1m]`, a gateway alias currently mapped to a non-Claude model; this is not a Claude-native model claim. The exact resolved value is recorded in ADR-0016 and the #251 Work record. Broader engine-scope changes remain tracked through #6.
